# 变更记录

## 1.2.0 — 2026-09-15

**`never_used` 不再对「元设定」误报；并给出 L3 创作层的实现方案。**

起因是首次在一部小说的全库跑 `check`：18 项问题里有 10 项是「已登记但正文未出现」，逐条核对后发现
**其中 6 项根本不是问题**——它们约束的是「怎么写」，整卡名本就不该出现在正文里。
`check` 用一个不成立的期待去衡量它们，于是永久误报。

### 新增

- **`元设定` 豁免机制**：卡片 front matter 写 `tags: [元设定]` 即豁免「已登记但正文未出现」判定，
  改判「其实例是否落地」——只看 `## 档案` 段里的实例名（不把 `## 关系` 段的卡片间引用当正文实例），
  全部落空才报 `meta_never_used`。输出末尾提示「已豁免 N 项元设定卡片」。
  - 判定口径写明：`元设定` 是**人工标签**，不是自动推断；默认「世界里有什么」，
    只有明确约束「怎么写」的才打此标签。防止「报错了就打标签绕过去」。
- **`docs/creation-layer.md`**：L3 创作层实现方案。定位＝**薄编排层 + 可回查评审报告**，
  不是第四个库。逐个说明「抄哪个现有项目的哪个做法」：
  nms（幂等预检 / Pydantic 校验 / 断点续传原子写 / savepoint 粒度 / 重试上限 3 / `--mock` 双路径）、
  nah（写前 brief、写后 check、动过就 sync 的强制工作流）、
  xs（分级 + 可溯源）。分阶段推进，**第一阶段先做只读 `review`**。
- **测试 2 项**（共 52 项）：元设定豁免生效、元设定卡片实例未落地时仍提示。

### 修改

- **`docs/architecture.md`**：§5 缺口表补 3 行新缺口（`never_used` 元设定误报、只认整卡名、
  与 nms 对接列为后续阶段）；L3 小节指向 `creation-layer.md`；新增 §5.1 说明豁免机制。
- 某小说工作区里 6 张卡片补 `tags: 元设定`：三主体架构 / 派遣制 / 世界×英雄配置 /
  写作节奏·三段循环 / 设定修正三规则 / 变身规则。

### 实测（某小说 · 89 章）

- `check` 问题数 **18 → 3**：
  - 断链 0 / 别名冲突 0 / 单向关系 **5 → 0** / 非稳定 0
  - 已登记但正文未出现 **10 → 3**（全是已判定的合理项：素材池与设定侧命名）
  - 正文出现但未登记 **3 → 0**
- 新增 4 张卡片（王姨 / 张叔 / 变形车 / 顾青），资产总数 24 → 27。
- 关键发现：**顾青**（ep_055–ep_061 共 70 次出场）此前完全未登记——`orphan` 漏掉它是因为
  正文里从未有人「对顾青说」这类句式，全是叙述视角描写。这是句式启发式召回有限的实例证据。

### 已知局限

- 同 1.1.0（orphan 句式启发式、IP 库无实体名录）。
- 新增：`元设定` 豁免依赖人工打标签，存在被滥用的可能，故把口径写进 `docs/architecture.md` §5.1。

## 1.1.0 — 2026-09-15

**补齐一致性校验的反方向：`orphan`（正文出现但资产库未登记）。**

原先 `check` 只查「登记了但正文没出现」——那是应然落空；反方向「正文冒出库里没有的名字」
恰恰是 **AI 现编设定的入口**，之前只有人工对单章跑 `scan` 才会暴露。本版把它做成全库扫描。

### 新增

- **`nah orphan`**：全库反向扫描，把候选分为三类
  - **未登记** —— 两边都没有 ← 重点复核（AI 现编入口）
  - **原作已知** —— 命中外部 IP 证据库，属 L1 知识层，无需登记
  - **已登记** —— 正常命中资产库
- **抽取规则**（中文散文没有双链标记，故用句式启发式）
  1. 说话动词锚点（说/道/问/答/喊/叫）→ 向前回看本分句窗口；
  2. 定位介词对象（对/跟/向/和/与），取最后一个介词之后的名词短语；
  3. 取「最后一个『的』之后」的中心词，剥前导虚词与尾部助词；
  4. **词频裁剪**：候选收缩到仍在全文高频出现的最长前缀；
  5. 代词/虚词打头、含代词、常见名词一律过滤。
  另有一条**称谓式**规则（龙叔 / 小玉姐），并过滤「动词+名字+称谓」的粘连。
- **IP 证据库对接**：`workspace.json` 新增 `ip_evidence`（外部 `evidence.sqlite3` 路径列表，只读、可选）。
  命中即判为原作角色，避免输出被成龙/小玉这类原作人物淹没。**这是 L1↔L2 的唯一耦合点。**
- **`check` 并入反向扫描**：六类审计，闭环。
- **文档**：`docs/architecture.md` —— 整条创作管线的五层分工
  （规范层 / 知识供给 / 本书事实（应然∥实然）/ 创作层（缺位）/ 作品本体）。
- **测试**：新增 14 项，覆盖抽取规则、三分类、词频门槛、IP 库配置解析（共 50 项）。

### 实测（某小说 · 89 章）

- 候选 23 项 → 未登记 **3 项**（王姨 / 张叔 / 变形车）、原作已知 10 项、已登记 4 项。
- 全链耗时 **0.5 秒**。

### 已知局限

- 属**句式启发式**：精度高、召回有限，定位是「人工复核清单」而非自动拦截器。
  想要更稳的召回，建议写作时在正文/大纲保留 `[[双链]]`（精确引用，优先级最高）。
- IP 证据库目前只有全文索引、没有实体名录，判据是 `LIKE` 全文命中，同名词可能误判。

## 1.0.0 — 2026-09-15

**首次作为独立项目封装。**

此前这套工具与小说数据混在同一个目录（`<小说>/设定资产/` 里既有代码又有卡片），
且硬编码了具体小说的结构。本版本把它抽成独立引擎，与数据彻底分离。

### 新增

- **工作区机制**：一部小说一个工作区，同一个引擎可管多部小说。
  - `workspace.json`：工作区配置（项目名 / 类型集合 / 正文章节目录）。
  - `nah.config.json`：项目级工作区注册表（`ws add/use/rm/list`）。
  - 根目录解析优先级：`--root` > `NAH_ROOT` > `--ws` > 配置默认 > 当前目录。
- **统一 CLI**：原先要分别调用 `asset_hub.py` 与 `asset_db.py`，现在合并为单一 `nah`；
  `--root` / `--ws` 可写在任意位置（子命令前后都行）。
- **`nah init`**：一条命令生成新工作区骨架，可自定义类型集合与正文章节目录。
- **`nah ws show`**：查看当前解析到的工作区及其配置。
- **测试**：36 项单元测试，全部在临时目录内运行，不触碰真实工作区。
- 工程化文件：`pyproject.toml`（可选安装成 `nah` 命令）、`LICENSE`、`.gitignore`、
  `templates/card.md`、`docs/design.md`。

### 修复

- `history` 在改名后断链：改名会把实体 id 从「类型/旧名」换成「类型/新名」，
  改名前的历史查不到。现在会**沿改名链回溯前身**，把断掉的历史接回来。
- 配置目录不存在时写 `nah.config.json` 会抛 `FileNotFoundError`。
- SQLite 连接未关闭导致的 `ResourceWarning` 与文件句柄泄漏（CLI 退出前统一收口）。
- `re.split` 位置传参 `maxsplit` 的弃用警告。

### 解耦（原先是写死的）

| 原来 | 现在 |
|---|---|
| 根目录 = 脚本所在目录 | 由工作区解析链决定 |
| 项目名 = 工作区上级文件夹名 | 取 `workspace.json` 的 `name` |
| 正文章节目录写死为 `../processed/raw` | 取 `workspace.json` 的 `chapters_dir` |
| 固定 7 类资产类型 | `workspace.json` 可自定义类型集合 |
| 两套命令两套入口 | 合并为单一 `nah` CLI |
